# 006 跨模块读取：使用方定义端口

状态：已采纳，2026-11-19

## 背景

[005](005-module-interaction.md) 定了读取事实时调用对方的读接口，但没有定实现方式。用例库需要 Access 回答"某项目有没有某个 `proj_ver`"，而用例库的服务层只持有自己的 UoW，没有 Access 的会话。如果直接 import Access 的读函数，调用方无处取得 Access 的 UoW，只能把 `session_factory` 传进用例库，基础设施会漏进领域模块。

## 决定

由使用方定义最小端口。用例库在 `ports.py` 里声明 `ProjectVersionLookup`，只回答版本是否存在；实现在集成层 `stsd.integration.access`，包装 Access 的 `get_project_version`；由组装根 `stsd.bootstrap` 注入。用例库核心代码不 import Access，集成层与组装根是仅有的可以同时接触两个模块的地方。

端口只读不可变事实，必须在用例库的写操作之前调用；适配器自持只读事务，不参与用例库的事务。

## 理由

把"用例库需要什么"和"Access 恰好提供什么"分开，用例库可以脱离 Access 数据单独测试，依赖方向也明确：模块 → 自己定义的端口 ← 集成实现 → 对方公开接口。直接 import 的替代方案在当前结构下要求把对方的基础设施一起传进来，代价更大。

## 后果

多一个端口和一个适配层。端口形状与 Access 现有读接口不完全对齐：存在性检查走 `get_project_version`，会读出整个版本和全部文档，这是当前接受的开销；批量场景成为瓶颈时，应先在 Access 增加轻量查询，再改适配器。适配器必须把 Access 的"项目不存在/版本不存在"折叠为 `False`，这条错误折叠是端口的契约。跨模块读是两个独立事务，只允许用于不可变事实。
