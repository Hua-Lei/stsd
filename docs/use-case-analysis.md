# 用例分析

> 本文描述用户的目标。业务规则见 [modules/](modules/) 下各模块的规格，术语见 [domain-model.md](domain-model.md)。

## 1. Access 系统

负责平台侧的账号与项目接入，是其他模块的前置。

| 编号 | 用例 | 说明 |
| --- | --- | --- |
| A1 | 创建用户 | 创建平台账号 |
| A2 | 创建 Project | 用户创建一个 Project，并提供链接 Web 相关的基本配置 |
| A3 | 创建项目版本 | 用户在 Project 下添加一个项目版本，并提供该版本对应的需求文档和接口文档 |
| A4 | 添加项目成员 | 用户在一个 Project 中添加其他用户 |
| A5 | 查看用户下的 Project | 列出当前用户所属的 Project |

## 2. 项目内管理

以 Project 为边界，管理平台内的核心资产。

### 2.1 用例库

用例库是项目内的分层资产容器，核心对象为 Section 与测试点（TestPoint）。

| 编号 | 用例 | 说明 |
| --- | --- | --- |
| U1 | 增加 / 删除测试点或 Section | 用户在用例库的某个位置增加或删除测试点或 Section |
| U2 | 修订测试点 | 项目版本推进或需求变化后，用户为受影响的测试点产生新的修订 |
| U3 | 为修订补充实现 | 用户为一条修订补充可执行的实现 |
| U4 | 读取 Section 子节点 | 用户浏览用例树，查看某个 Section 下的内容 |

### 2.2 审计与冻结

| 编号 | 用例 | 说明 |
| --- | --- | --- |
| U5 | 审计并冻结 | 用户审计一条修订，通过后它成为不可变的正式资产，可以被任务引用 |

## 3. 任务系统（Task）

| 编号 | 用例 | 说明 |
| --- | --- | --- |
| T1 | 组装任务清单 | 用户为一次测试选定项目版本，再从用例库挑选已冻结的修订加入任务清单 |
| T2 | 保存任务清单 | 用户组装完成后保存清单，此后该清单可以被启动 |
| T3 | 启动任务 | 用户启动一个已保存的任务，交给执行器执行 |

## 4. 执行器

| 编号 | 用例 | 说明 |
| --- | --- | --- |
| E1 | 执行一个任务 | 执行任务清单中的全部测试项 |
| E2 | 测试性执行一个测试点 | 对单条修订试跑，用于冻结前验证，不进入正式任务 |

## 5. 结果存储 & 分析系统

> 分析能力暂不展开，当前阶段只保证结果存储。

| 编号 | 用例 | 说明 |
| --- | --- | --- |
| R1 | 读取任务结果 | 用户读取一个任务对应的执行结果 |

## 6. Agent 模块

| 编号 | 用例 | 说明 |
| --- | --- | --- |
| G1 | 生成测试点 | 用户点击生成测试点并给出 Prompt，Agent 生成大致的修改参考，经用户审批 |
| G2 | 分析当前变更 | 与 G1 类似，同样需要用户审批 |
