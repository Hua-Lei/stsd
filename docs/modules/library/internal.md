# 用例库内部规则

> 本文是当前的实现规则，不是对外契约。别的模块依赖的部分见 [library.md](library.md)。

## 两种存储

实现的文件内容进文件系统，元数据（包内路径、内容哈希）进 SQL。存储通过端口读写，端口定义在 `library/ports.py`，实现在 `library/adapters/`。别的模块只能通过 `get_implementation_files` 取内容，存储布局不对外可见。

文件内容按**内容哈希**寻址，不按可覆盖的文件 id 存一个路径。好处是连着的：内容从不原地修改，所以编辑草稿不可能改到已冻结修订读到的字节；`ReviseTestPoint` 之后多数文件没变，新修订直接引用同一份内容，不复制；清理规则也简单到可以放心跑。

`File` 在包内的身份就是它的路径，不需要额外的 id。要支持重命名后保持身份才需要，现在没有这个需求。

## 写入顺序

内容先落盘，元数据后提交。两种失败不对称：先写内容后提交失败，留下一份没人引用的内容，是垃圾，可以扫掉；反过来先提交后写内容失败，留下一条指向不存在内容的记录，这份实现就读不出来了。

删除永远不同步做。从草稿包里移除一个文件只是去掉元数据行，那份内容可能还被别的修订引用。真正的内容删除交给后台清理：没有任何元数据行引用、且超过一定时间的内容才删。

## 聚合的装载量

TestPoint 聚合带着全部历史修订，所以修订必须是小的元数据，内容不进 SQL。这样装载一个测试点的代价只随历史长度增长，系数很小；冻结时的校验也只需要元数据。
