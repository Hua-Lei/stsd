# 001 proj_ver 是修订的说明性信息

状态：已采纳，2026-11-18

## 背景

最初的设计用 `(testpoint_id, proj_ver, revision_ver)` 标识测试点的一个版本。项目版本每推进一次，每个测试点都要产生新版本，即使内容没有变化。后续任务完全可以复用早先项目版本下的实现，`proj_ver` 作为标识的含义逐渐退化成生命周期标记。

## 决定

修订由 `(testpoint_id, revision_ver)` 标识，`revision_ver` 是测试点自己的线性序号。`proj_ver` 记录这次修订针对哪个项目版本写成，作为说明性信息保存，不参与标识。

## 后果

项目版本推进时，内容未变的测试点不产生新修订，任务自己决定选用哪一条修订。同一条已冻结的修订可能被多个项目版本的任务共用。如果某个项目版本的需求变了而测试点没有及时修订，任务会沿用旧修订，这一风险属于项目版本推进流程的设计范围，留待后续处理。
