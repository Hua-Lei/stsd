# 007 应用入口：只接收命令，工作单元在模块内部创建

状态：已采纳，2026-11-19

## 背景

模块门面的服务函数形状是 `(uow[, dep], command)`，调用方要自己创建工作单元。组装根曾经同时暴露 UoW 工厂和用例函数，结果事务所有权有两处：服务内部 `with uow` 并 `commit()`，调用方又以为自己在控制事务，把同一个 UoW 再包一层 `with` 会二次进入并替换会话。同时 `AppContext` 里的用例字段被标注为 `Callable[..., object]`，类型在入口处丢失；两个用例还需要外部端口，签名与其他用例不一致。

## 决定

应用外层入口统一为 command-only：调用方只传命令对象，工作单元由每个模块的装配入口 `build_access_app` / `build_library_app` 在每次调用时新建，事务边界仍由服务层的 `with uow` 决定。组装根返回 `AppContext(publisher, access, library)`，不再暴露 UoW 工厂、会话或端口适配器。

不引入命令总线：每个命令与处理函数一一对应，没有多播需求，而总线会丢掉返回值类型。跨模块事件继续使用 `EventPublisher` 端口；进程内实现是 `stsd.shared.events.MessageBus`，外部 broker 将来作为该端口的另一种适配器加入。模块内部事件总线也暂不引入：当前没有事件，需要时由模块提供注册入口，在组装根调用，不为将来预留空壳。

## 理由

事务所有权收敛到服务层，调用方不必也无法再管理会话；入口恢复完整类型；组装根不再手工镜像每个用例；跨模块依赖与事件分发各自只有一个方向。

## 后果

调用方不能把多个用例放进同一个事务，这与"一个用例一个事务"一致。模块门面仍保留 `(uow[, dep], command)` 形状，供模块内测试和组合使用。新增一个用例需要同步服务函数、命令对象、模块 App 字段和装配函数四处。事件机制尚未实现，第一条事件出现时再落模块的注册入口。
