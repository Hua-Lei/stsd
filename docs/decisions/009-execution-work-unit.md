# 009 执行的工作单元是一个任务

状态：已采纳，2026-11-24

## 背景

一个任务里的修订可能要求不同的 python 版本或不同的依赖集，塞进同一个容器跑不了。据此曾把工作单元定成"同平台同依赖签名的一批修订"，一批一个容器。

## 决定

工作单元就是一个任务。`TaskStarted` 的订阅者只插入一行 `task_id` 入队；读任务详情、读各修订的实现、算环境签名、定执行顺序，都发生在 worker 领取之后。否决了按依赖签名提前切批入队。

## 理由

切批要求订阅者先读详情再算签名才能入队，而它所处的位置——发布方事务刚提交、同步调用链上——要求入队是一次极小且幂等的写入。

更根本的是切批把"怎么跑"提前到了排队时。容器复用不需要队列参与：把修订按环境签名排序后顺序执行，同环境的修订天然连续，一个容器就够。队列只需要回答"哪个任务还没跑"。

## 后果

任务内部串行，任务内吞吐上限是 1，并行只存在于任务之间。对真实 API 来说这也是更安全的默认值。

任务不能整体重试：每条修订的结论要单独幂等落库，重试时跳过已到终态的修订，Job 从原子变成可续跑。

任务级时长没有上界，所以租约必须是心跳式的，不能用固定超时——既不误杀长任务，又能及时回收死掉的 worker。
