##  页面设计

> v0.1 · 2026-11-11 · 设计载体为桌面 Web 页面；所有编号、数量、时间和测试数据均为示例。本文描述业务与交互，不表示后端已具备相应能力，不涉及框架、应用代码或 API 路径。

### 1. 页面结构、视觉方向与公共布局

![图 1：页面结构和主要任务路径](figures/01-map.png)

图 1 图源：[SVG](figures/01-map.svg)。后续每张图均有同名 SVG；[绘图源文件](figures/draw_wireframes.py)保留坐标、文案和布局，供修改与重新导出。

| 页面 | 任务与去向 | 页面形式 |
|---|---|---|
| P00 项目入口 | 创建或进入项目 → P01；已有项目可直接进入 P02。 | 独立页；项目名也可在页眉切换。 |
| P01 文档 | 导入、阅读、查看版本与差异 → P03 发起生成或修订。 | 列表与正文同页；导入用弹窗，版本差异为页内双栏。 |
| P02 用例库 | 浏览模块、测试点和实现 → P03 生成、P04 审核、P05 选用。 | 左树右详情；测试点／实现内容和历史用标签切换。 |
| P03 AI 任务 | 发起与查看规划、实现、修订任务 → P04 看产出。 | 任务列表＋任务详情；列表点击进入同一工作区内的详情页。 |
| P04 变更审核 | 看摘要、校验、差异，批准并合并或拒绝 → P02。 | 审核列表＋独立详情；审核决定固定在详情底部。 |
| P05 任务清单（草案） | 加入实现、预览、锁定、复制 → P06 配置。 | 清单列表＋详情；添加、锁定确认和复制用弹窗。 |
| P06 执行记录 | 配置并发起执行、查历史 → P07。 | 历史列表；执行配置是弹窗。 |
| P07 执行结果 | 看汇总、筛选异常、逐条读证据 → P05 复制回归。 | 独立详情页，主结果表＋右侧证据面板。 |

**公共布局：**草图画布 1440×900。顶部显示产品名和当前项目；左侧约 205 宽放六个业务入口；中间内容区页首左侧为标题和面包屑，右侧为本页主要操作。局部筛选紧贴列表，行操作放行尾。内容长时允许滚动，审核决定栏固定在内容区底部，不覆盖最后一条差异。

**舒适度建议：**正式视觉阶段采用清晰的灰阶背景、白色内容面板和一种主操作强调色。主内容使用约 16–18px 正文字号、1.5 倍左右行高；标题约 24–28px；常用间距取 8／16／24，表格行高约 44–52px。每个任务区域保留一个明显的主操作，危险或否决操作次一级；不要用颜色作为唯一状态依据。图里的深灰按钮表示主要动作，不是最终配色。按钮用动词＋对象，避免只有图标或“确定”。

较窄的 Web 窗口可折叠左导航；差异双栏切换为上下对照，标明“修改前／拟修改后”；结果详情改为覆盖式侧栏。表格保留 ID、标题、状态，其余列横向滚动；不以压小字体换取塞入所有字段。按钮和输入框有可见焦点，弹窗可取消，关闭后回到发起操作的位置。

### 2. P00 项目入口

![图 2：项目列表与新建入口](figures/02-projects.png)

[SVG 图源](figures/02-projects.svg)。项目管理能力尚待确认，本页为建议界面。

| 位置／按钮 | 用户动作与后续反馈 |
|---|---|
| 页首右上“新建项目” | 打开项目名称必填、说明选填的弹窗。右下“取消／创建并进入”。重名或输入错误在字段附近提示，创建失败保留输入。 |
| 搜索区 | 按项目名查找；无匹配显示“没有匹配项目”，保留搜索词并允许清空。 |
| 每条项目右侧“进入项目” | 进入该项目的用例库；空项目进入文档页并说明先导入哪些材料。页眉显示当前项目，避免跨项目误操作。 |
| 页眉项目下拉 | 仅切换项目，不改变运行中任务归属。存在未提交编辑时提示“继续编辑／放弃并切换”。 |

首次无项目显示简短说明和“新建项目”；加载失败提供“重试”，不能显示成空项目库。暂不增加永久删除项目操作。

### 3. P01 文档与版本

![图 3：文档正文、版本与生成入口](figures/03-documents.png)

[SVG 图源](figures/03-documents.svg)。中间正文只读，右侧保留版本与下一步；文档种类可以切换。主操作“导入文档版本”在页首右侧。“更多”仅收纳已经可用的次要动作，例如查看全部版本，不放未定义业务。

| 操作 | 完成任务的步骤与反馈 |
|---|---|
| 导入文档版本 | 弹窗选择需求／接口文档，填写标题并粘贴正文，右下“取消／保存新版本”。当前材料没有明确上传解析能力，首版不承诺 PDF、Word 自动解析。保存中禁用重复提交；成功选中新版本，显示版本号和“已保存文档，尚未修改用例库”。 |
| 切换历史版本 | 正文标明“历史版本，只读”；返回当前版本不会丢失历史内容。 |
| 查看版本差异 | 选择同一文档的旧、新版本，左右标明版本名；无差异明确写“无文本变化”。不足两个版本时禁用并解释原因。 |
| 生成测试点 | 选择本次使用的具体需求与接口文档版本，进入 P03 的发起弹窗；缺少工作流所需材料时指出缺少项。 |
| 基于更新提出修订 | 选择新旧文档版本并补充目标，进入 P03；即使已有文本差异，也不能显示“所有受影响测试点已自动识别”。 |

首次空白态分列需求和接口文档的缺失提示，主按钮保持“导入文档版本”。导入失败保留正文；文档存储成功但生成任务失败时分别提示，不能要求用户重复导入。

### 4. P02 用例库与节点详情

![图 4：目录、测试点与实现列表](figures/04-library.png)

[SVG 图源](figures/04-library.svg)。借用 TestRail 的目录＋资产详情组织，业务层级为模块 → 测试点 → 实现。目录默认不显示废弃对象，勾选“显示废弃项”后附明确标签。

| 区域／按钮 | 交互与反馈 |
|---|---|
| 左侧树、名称／ID 搜索、状态筛选 | 展开目录或选中测试点，右侧显示路径、稳定 ID 和当前修订。节点移动后 ID 不变。某分支加载失败就在分支内“重试”，不清空整个库。搜索范围明确为当前项目。 |
| 测试点内容／测试实现／版本历史 | 内容展示标题、验证目标、理由、状态；实现列表展示标题、ID、修订和审核状态。选中实现后显示步骤、请求、变量提取、断言。历史展示时间、修改者、说明和可读旧内容，不提供直接覆盖恢复。 |
| 页首“AI 规划” | 打开发起规划弹窗；最终到 P03，再到 P04，而不是生成后立即入库。空库也保留此入口。 |
| 详情“生成实现” | 仅针对已获批测试点启用，用户确认本次选中的测试点版本。未获批时显示“先完成测试点审核”。 |
| 页首“新增”／详情“编辑提案” | 新增菜单为模块、测试点、实现（按所选父节点限制）；填写语义字段与修改说明，右下“取消／保存提案”。实现编辑用步骤、输入和断言分组，原始结构作为折叠查看内容。成功后提示“已形成待审核变更集”，可跳 P04，正式库保持原状。 |
| 更多中的“移动／废弃” | 移动选择目标目录并预览新路径；废弃确认框说明受影响节点数量，均以“提交变更提案”结束。递归废弃是否允许依后端确认；未确认前只允许提出单节点废弃。 |
| 已获批实现复选框＋“加入任务清单” | 选择目标草稿或“新建草稿”；未获批行禁选并解释。成功显示实际加入的 ID 和版本；重复／无法加入逐条提示。 |
| 详情中的“查看相关待审核提案／执行历史” | 分别跳 P04 或在 P06 中按实现筛选，避免用户以为当前正式内容就是提案。 |

无实现时显示“测试点已获批，可以生成实现”；测试点未获批时引导查看审核；无目录时显示“导入文档并开始规划”，也提供人工新增。手动编辑过程中离开先提示未保存内容；提交校验失败在相应字段定位，不抹掉草稿。

### 5. P03 AI 任务：发起与进度

![图 5：AI 任务详情与过程反馈](figures/05-session.png)

[SVG 图源](figures/05-session.svg)。独立“AI 任务”入口是交互建议，便于离开页面后找回。列表列出任务编号、类型、目标、状态、开始时间和产出；支持类型／状态筛选，行尾“查看”。

**发起弹窗：**顶部选择规划／实现／修订；中部显示项目、固定文档版本及选中的测试点版本；目标输入框可补充“补充姓名长度边界”等要求。实现类型只能使用已获批测试点。右下“取消／开始生成”；开始后显示“任务已创建 S-018”，进入详情，不声称已生成成功。

| 阶段 | 用户看到什么／可做什么 |
|---|---|
| 运行中 | 类型、输入版本、计时和事件列表；已知时展示轮次，不显示虚构百分比。详情分任务过程和产出区，错误事件可以展开。提供“刷新状态”“返回任务列表”。 |
| 任务完成且有变更集 | 显示“生成完成，等待人工审核”，主按钮“查看变更集”到 P04。正式资产数量不提前增加。 |
| 任务完成但无变更 | 显示完成说明“未提出修改”，不提供空审核按钮，也不显示生成失败。 |
| 失败、超时或达到轮次上限 | 列出停止原因、已保留产出，说明正式库未更改；“按原输入新建任务”先打开可修改的发起弹窗，确认后创建新编号，旧记录保持。 |
| 状态获取失败 | 保留最后一次成功状态及更新时间，提示“状态暂未更新”；“重试获取状态”不重新生成任务。 |

运行期间不提供中途追加指令；新的要求通过后续修订任务提出。若后端将任务失败但保留合法提案，该提案仍必须独立审核，不能用任务状态代替校验与审批。

### 6. P04 变更审核

![图 6：变更列表、前后差异和固定审核栏](figures/06-review.png)

[SVG 图源](figures/06-review.svg)。入口列表默认“待审核”，另有“已合并／已拒绝”。列出编号、来源（人／AI）、阶段、变更项数量和时间。点击行到详情。

**详情布局：**上方摘要和程序校验；左列为变更项列表；中右为修改前、拟修改后；底部固定审核决定栏。新增项旧侧显示“不存在”，废弃项显示“拟废弃，保留历史”，移动项突出旧路径与新路径。折叠长步骤、请求和原始内容，不能只展示原始 JSON。图中的 400 是示例业务预期，实际断言应依据所选文档确认。

| 按钮与位置 | 步骤与反馈 |
|---|---|
| 变更项列表 | 切换查看每项；标明新增／修改／移动／废弃和基础修订。完整变更集作为一个决定，不提供后端尚未支持的逐项合并。 |
| 底部次要按钮“拒绝” | 打开理由框，右下“取消／确认拒绝”；理由必填是本稿建议，需审核记录支持。提交后状态变为“已拒绝”，资产不变；AI 来源提供“按反馈新建修订任务”。 |
| 底部主按钮“批准并合并” | 打开摘要确认：对象数量、操作类型、校验结果；“返回检查／确认批准并合并”。提交中禁用两个决定按钮。服务确认成功后显示“已合并”和实际产生的修订，提供“查看用例库”。 |
| 返回审核列表 | 保留筛选；已合并或已拒绝详情只读，不再提供重复审核。 |

程序校验阻塞错误使批准按钮禁用，旁边说明错误；普通警告列出风险，不一律禁用。批准时若因基础版本已变或对象不可用而被后端拒绝，显示“未合并，请查看最新内容”，保留提案并允许刷新；不承诺自动解决并发冲突。提交响应丢失时先“查询审核结果”，未确认前不自动重发决定。

**两次关卡的后续：**测试点变更集合并后引导“生成实现”；实现变更集合并后引导“加入任务清单”。批准测试点后不能直接把不存在或未获批的实现送去执行。

### 7. P05 任务清单（依据任务草案）

![图 7：清单条目、预览与锁定](figures/07-tasklist.png)

[SVG 图源](figures/07-tasklist.svg)。列表列出名称、目标软件版本、草稿／已锁定、条目数量和更新时间；页首“新建清单”。新建弹窗填写目标软件版本（必填）、名称（选填）；确认创建后进入草稿详情。若版本选项尚无统一来源，展示待接入说明，不能让任意数字充当已验证版本。

| 控件 | 草稿态行为与反馈 | 锁定态行为与反馈 |
|---|---|---|
| 添加用例（局部工具栏左） | 弹窗搜索并勾选已获批实现，右下“取消／加入选中项”。默认尾部追加；每行展示固定 ID、修订、标题及可用性。 | 不显示编辑按钮，说明“内容已锁定，修改请复制为新清单”。 |
| 行尾“移除” | 只从本清单移除，明确“不会废弃库内实现”。 | 不可用。 |
| 固定版本／版本警告 | 在加入或复制时就展示实际固定版本。若适用版本已更新，提示“本条仍使用 r1”，不在刷新或锁定时自动换成 r2。指定旧版用明确“手动指定”标签；是否能指定需后端规则确认。 | 只读，执行仍用锁定内容。 |
| 页首“预览并锁定” | 展开预览：实际版本、条目数、警告与阻塞项；底部“返回编辑／确认锁定”。非空且后端校验通过才成为“已锁定”；失败逐条列出原因并保留草稿。 | 替换为主按钮“配置并执行”，到 P06。 |
| 复制为新清单 | 输入新目标版本、名称并选择模式，成功得到新的草稿，不修改原清单。 | 同左，用于回归或同版本重跑。 |

**复制模式用人能理解的文字：**“保留原实现版本”用于同版本重跑／有意验证旧断言；“按新目标版本选择适用版本”用于常规回归，但必须先确定版本规则。后一种在复制时即固定并显示新版本，列出旧→新对照；失败条目单独标明，不能悄悄丢失。默认优先常规回归模式，但规则未接入时禁用该选项并解释，不假定数字大小代表适用性。

**诊断反馈：**重复项显示“已在清单中，未重复加入”；无适用版本、找不到实现或指定修订不存在时逐行显示加入失败。存在更新或已废弃引用按草案先展示警告；锁定时仍由后端判定引用是否可用。预览只是报告，不修改内容。草案明确尾部追加，故本稿不提供尚未约定的拖动排序。列表行号不承诺不同用例间共享变量或依赖。

清单名称编辑能力依草案可在锁定后保留，但必须与修改内容分开；内容指纹等技术字段收在“记录信息”折叠区，不要求用户填写。上次通过的用例不默认剔除；是否免测必须有内容未变和其他规则依据，不能靠相同 ID 判断。

### 8. P06 执行记录与执行配置

![图 8：执行历史背景上的配置弹窗](figures/08-runs.png)

[SVG 图源](figures/08-runs.svg)。历史列表列出执行编号、目标软件版本、清单及固定版本、任务状态、用例结果统计、时间。筛选按状态、清单、实现；点击执行行进入 P07。空历史显示“还没有执行记录”，引导回用例库选已获批实现，不提供无上下文的执行按钮。

| 步骤 | 控件与反馈 |
|---|---|
| 打开配置 | 从已锁定清单点击“配置并执行”；若 M2 走直接选择，则显示所选实现和固定版本汇总，并重新核验均已获批。 |
| 填写环境 | 展示环境名称、被测服务地址、初始变量、单请求超时；必填、单位和错误在字段旁。初始变量的敏感值默认遮蔽。保存环境模板属于待确认能力，首版不增加独立环境管理页。 |
| 点击右下“开始执行” | 校验通过后显示“提交中”，阻止重复点击；取消按钮只在未提交时关闭弹窗，不会取消已接受任务。 |
| 创建成功 | 获得执行编号后进入 P07，显示“等待执行”；不能直接显示成功率。 |
| 创建失败或结果不明 | 明确失败时保留配置供修正；响应不明时提示先检查执行记录，不自动创建第二次。 |

周报的接口无响应 6 秒内报告（含重试）与单请求超时配置需要统一；不在草图填一个默认值假装满足要求。历史记录“再次执行”也应先打开配置确认并生成新 Run，不改写旧结果。锁定清单复制可直接到 P05；即使未来库内容更新，本次历史仍打开实际执行快照。

失败只表示证据不符合断言或执行遇到问题，不直接显示“已发现产品缺陷”。AI 失败归因与人工确认缺陷若后续纳入，在本页增加有来源的分析区；本稿不提供假入口。结果获取失败保留已有内容，显示最后更新时间与“重试获取”；重试读取不触发重新执行。

### 10. 跨页任务路径与反馈闭环

| 用户要完成的任务 | 页面与主操作顺序 | 每一步的可见确认 |
|---|---|---|
| 从零建立测试资产 | P00 进入项目 → P01 保存文档 → 生成测试点 → P03 查看产出 → P04 批准并合并 → P02 生成实现 → P03 → P04 再次批准 | 文档有版本号；生成有任务号；提案明确“待审核”；每次合并有新修订；两次审核均不会被自动跳过。 |
| 选定范围执行 | P02 勾选获批实现 → P05 加入草稿 → 预览并锁定 → P06 配置并执行 → P07 | 加入后显示实际版本；锁定后内容不可编辑；提交后出现执行编号；结果逐条出现；最终展示通过／失败／错误，不只给一个“成功”。 |
| 文档更新后维护 | P01 保存新版本 → 阅读文本差异 → 提出修订 → P03 → P04 → P02 | 文档版本增加不改正式库；AI 影响判断作为提案；合并后才能看到新正式资产；旧执行记录仍可读。 |
| 人工修改用例 | P02 编辑提案 → 保存提案 → P04 核对差异 → 批准并合并 | 编辑时是未提交内容；保存后是待审核提案；批准成功后才是新正式修订。 |
| 拒绝不合适的 AI 产出 | P04 拒绝并说明 → 按反馈新建任务 → P03 → 新变更集 | 原提案保留已拒绝状态；新任务与新提案使用新编号；旧记录不改写。 |
| 回归重测 | P07 复制清单回归 → P05 确认目标版本和条目版本 → 锁定 → P06 → 新 P07 | 原结果保留；复制后的清单是草稿；版本变化明确展示；新执行单独记录。 |

统一反馈方式：字段问题贴近输入；页内可恢复错误用提示条；最终状态变化保留在页面而不只出现几秒的弹出提示。提交按钮在处理期间显示动作名称与省略号；后端未确认前不显示“已合并”“已锁定”或“已开始运行”。空白、筛选无结果、加载失败分别表达，避免把加载错误误认成数据不存在。
