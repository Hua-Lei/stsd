# 002 实现与冻结

状态：已采纳，2026-11-17 确定实现的归属，2026-11-18 确定冻结条件

## 背景

测试点描述要验证什么，实现描述怎么验证，二者在需求分析中是两个层次。一条修订产生时只有内容，实现需要之后补充。

## 决定

每条修订至多有一个实现。新修订的实现为空，通过 `AddImplementation` 补充，冻结之前可以覆盖。冻结要求实现非空，冻结之后内容与实现都不可变，冻结不可撤销。

## 理由

已冻结的修订不能再修改。如果允许空实现冻结，这条修订永远无法执行，也无法补救，只能另开新修订。

## 后果

"先审核测试点、再补实现"这样的两段审核无法用冻结来表达。如果需要，由 Agent 模块的审批流程承担。
